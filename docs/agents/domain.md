# Domain Docs

Before exploring, read the root `GLOSSARY.md` (or `GLOSSARY-MAP.md` and relevant context glossaries) and relevant ADRs in `docs/adr/`. In multi-context repos, also check `src/<context>/docs/adr/`.

If these files don't exist, proceed silently. Don't suggest creating them upfront; create them as terms or decisions are resolved.

This repo uses the single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Use glossary terms in issue titles, proposals, hypotheses, and tests. If a needed concept is missing, reconsider the wording or note the gap for domain modeling.

If output conflicts with an ADR, surface the conflict explicitly rather than silently overriding it.
